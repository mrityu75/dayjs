## Part I: Exploration

| | Finding |
|---|---|
| Build / run | `npm ci` installs dependencies. `npm run build` runs the Rollup build and size check. `npm run babel` creates the ESM build. Day.js is a library, not a standalone application, so there is no `npm start` script. |
| Test | `npm test` runs timezone-specific tests and then the Jest suite with coverage. For focused tests, use `npx jest test/plugin/calendar.test.js --runInBand --coverage=false`. |
| Lint / format | `npm run lint` runs ESLint on `src/`, `test/`, and `build/`. `npm run prettier` formats documentation Markdown, not general JavaScript files. |
| Key directories and entry points | `src/index.js` contains the core Day.js implementation. `src/plugin/` contains optional plugins, `src/locale/` contains locales, `types/` contains TypeScript declarations, `test/` contains Jest tests, and `build/` contains build scripts. |
| Unstated conventions | Plugins extend `DayjsClass.prototype`. Tests are organized by core functionality, plugin, locale, and issue. JavaScript uses two-space indentation, no semicolons, and no trailing commas. Public API changes should update TypeScript declarations. |
| Off-limits (generated, vendored) | Do not edit generated build outputs such as `dayjs.min.js`, `/locale`, `/plugin`, `/esm`, root `index.d.ts`, and `locale.json`. Avoid `coverage/` and `node_modules/`. `CHANGELOG.md` is generated by semantic-release. `test/browser.spec.js` explicitly says not to modify it. |
